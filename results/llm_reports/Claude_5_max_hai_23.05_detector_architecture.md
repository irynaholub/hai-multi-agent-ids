# Process-Oriented Anomaly Detection Architecture - HAI 23.05

Configuration stage only. No anomaly detection is performed here and no statement is made about the cause of any deviation. The attack label columns shipped with the dataset are **not** used as input to this configuration and must not be used for calibration.

## 0. Input basis

**Dataset.** HAI 23.05 (HIL-based Augmented ICS Security Dataset, The Affiliated Institute of ETRI, CC BY-SA 4.0), published at `github.com/icsdataset/hai`. 86 process tags plus a timestamp column, sampled at 1 Hz with time continuity inside each file. Normal operation: `hai-train1` to `hai-train4`, 249 h total. Test files `hai-test1`/`hai-test2` contain labelled abnormal periods and are not used for configuration or calibration.

**Testbed.** Four coupled zones: boiler process **P1** (Emerson Ovation DCS, five feedback loops: pressure PC, level LC, flowrate FC, temperature TC, cooling CC), turbine process **P2** (GE Mark VIe DCS, one speed loop plus over-speed/over-vibration trip protection), water treatment process **P3** (Siemens S7-300, one level loop), and the hardware-in-the-loop simulation **P4** (dSPACE SCALEXIO: steam turbine model STM, hydro turbine model HTM, generator and grid models). P1 and P3 are physically real; P4 is simulated but exchanges signals with both in real time.

**Why this matters for detector assignment.** The zones are not statistically independent blocks of one wide table. Boiler pressure and temperature become the steam inlet conditions of the simulated turbine; the simulated grid frequency becomes the speed setpoint of the physical turbine; the simulated hydro model drives the physical pump and valve of the water treatment process. Those documented couplings are treated as causal relations and are the backbone of the consistency detectors below.

**Companion data not used here.** HAIEnd 23.05 (225 internal DCS points) and the published NetworkX graphs of the boiler control logic are available and would refine several assignments; this configuration is restricted to the 86 HAI 23.05 tags.

### Detector and zone dependencies

| Source | Target | Relationship |
|---|---|---|
| D1-SIGNAL-VALIDITY | all detectors | Gating: a tag that fails range or slew validation invalidates every residual and configuration score computed from it. |
| P1_STSP / P2_OnOff (mode tags) | all D2, D3 and D4 detectors | Mode segmentation: statistics, configurations and dynamics must be calibrated per operating mode, not over pooled data. |
| D3-P1-SETPOINT-CONFIG | D5-P1-PC-LOOP, D5-P1-LC-LOOP, D5-P1-FC-LOOP, D5-P1-TC-LOOP, D5-P1-CC-LOOP | A setpoint configuration flagged as unseen makes the corresponding loop residuals uninterpretable rather than anomalous. |
| D1-P1-DISCRETE-CONSISTENCY | D5-P1-PUMP-HYDRAULICS | Pump hydraulic regimes are conditioned on the running states; a discrete inconsistency explains the hydraulic residual. |
| D5-P1-FC-LOOP | D5-P1-LC-LOOP | Documented feedforward: the outflow demand is an input of the level loop, so a flow-loop fault propagates into the level residual. |
| D5-P1-TC-LOOP | D5-P1-HEAT-BALANCE | Controller-based and physics-based views of the same heat exchanger; agreement of both isolates sensor faults from control faults. |
| P1 zone | P4-STM zone | Boiler outlet pressure and temperature are the steam inlet conditions of the steam turbine model. |
| D5-P4-STEAM-TRANSFER | D5-P4-STM-POWER | The steam-condition transfer must be verified before the simulated power residual can be attributed to the machine model. |
| P4-STM zone | P2 zone | The simulator frequency deviation generates the speed correction and the automatic speed setpoint of the physical turbine. |
| D5-P2P4-SPEED-LINK | D5-P2-SC-LOOP | An abnormal setpoint transfer must be excluded before a speed tracking residual is attributed to the turbine controller. |
| D1-P2-MODE-INTERLOCK | D5-P2-SC-LOOP, D4-P2-SPEED-DYNAMICS | Mode selection determines which speed setpoint is active and therefore which residual is defined. |
| D1-P2-TRIP-LOGIC | D4-P2-SPEED-DYNAMICS | A legitimate trip breaks the normal speed trajectory; the dynamics detector must be suppressed while the trip is latched. |
| P4-HTM zone | P3 zone | Pumping and discharge demands for the pump and valve are generated by the pumped-storage model. |
| P3 zone | P4-HTM zone | Measured discharge, inlet pressure and reservoir level determine the simulated hydro power output. |
| D4-P3-LEVEL-CYCLE | D5-P4-HTM-POWER | A disturbed reservoir cycle changes the hydro power residual without any fault in the simulator itself. |
| D5-P4-STM-POWER, D5-P4-HTM-POWER | D5-P4-GRID-BALANCE | Grid frequency is a shared consequence of both machines, so the grid residual is only meaningful once both machine residuals are clean. |

**Common preconditions**

- Extract only `hai-train1` to `hai-train4` for calibration and training; keep the test files untouched.
- Drop the label columns before any fitting step.
- Segment by operating mode using `P1_STSP`, `P2_OnOff` and `P2_MASW` before computing any statistic, configuration set or dynamic model.
- Verify time continuity and gateway hold-last-value artefacts per file before pooling the four normal files.
- Detectors marked `none` need an engineering rule table only: ranges and Boolean domains from the technical manual, plus the interlock and protection rules listed in section E once validated.
- Detectors marked `relationship-learning` need an explicit input/expected-output split; the expected outputs are named in the Notes column and in section B.

## E. Unresolved configuration issues

1. Conflicting documentation for the cooling loop setpoint: the control diagram uses P1_PP04SP, while the normal-operation model lists P1_B2016 with a band of 26-28 for the same loop. P1_B2016 is simultaneously declared as the pressure loop setpoint with a band of 0.1-0.2 bar. The true cooling setpoint tag must be confirmed before D5-P1-CC-LOOP is calibrated.
2. Conflicting documentation for the flow loop setpoint: the control diagram uses P1_B3005 (return water tank discharge), while the normal-operation model lists P1_B400B (heating water tank outflow). The role of the second tag is unresolved; D5-P1-FC-LOOP currently carries both.
3. The relation between the demand tags (P1_B2016, P1_B4022) and the effective setpoint tags (P1_B2004, P1_B4002) is not documented. Whether the effective setpoint is a filtered, rate-limited or independent value determines whether the pair forms a valid residual.
4. P1_FT01 and P1_FT03 carry identical descriptions (flowrate of the return water tank) while their converted tags are described as inflow and outflow respectively. The flow direction of each transmitter must be confirmed before the mass balance is used.
5. The conversion function between the raw differential-pressure tags (0-2500 mmH2O) and the engineering flow tags (0-3190 l/h) is not given. It is needed both for the raw/engineering consistency check and for the tank mass balance gain.
6. Semantics of P1_PIT01_HH are ambiguous: a fixed high-high trip setting and a recorded running maximum require different rules. Its range is identical to the measurement itself.
7. Operating philosophy of the two main water pumps PP01A and PP01B (duty/standby, parallel, alternation schedule) is not documented, so the allowed joint state set is an assumption.
8. Interlock between the main tank supply valve P1_SOL01D and drain valve P1_SOL03D is assumed to be mutual exclusion. This must be validated; the conditions that trigger each valve are also unknown.
9. Whether P1_B4005 is the outer-cascade output feeding the inner flow controller, or the final valve demand, is not stated explicitly.
10. The turbine trip description is ambiguous about direction: it states that the turbine runs when the speed is above the trip rate, which contradicts the stated purpose of over-speed protection. The comparison convention for the signed vibration channels (signed value, magnitude, or band) is also unspecified.
11. P2_VTR04 is described as the limit for sensor P2_VIBTR03, which is most likely a typographical error for P2_VIBTR04.
12. P2_ManualSD has an engineering range of 0-3200 RPM but a declared normal command band of 11-12, which coincides with the range of the unrelated tag P2_VT01. Units and semantics need confirmation.
13. The gain, sign and exact role of P2_SCST are not documented beyond a proportionality to the simulator frequency deviation; it is unclear whether it is an input to the speed setpoint or a diagnostic output.
14. No nominal value or tolerance band is documented for the P2_24Vdc supply rail; only the transmitter range of 0-30 V is given.
15. All four P3 analog tags (P3_FIT01, P3_PIT01, P3_LCP01D, P3_LCV01D) are reported as raw 0-27648 counts with no engineering scaling, so the water treatment residuals cannot be validated dimensionally.
16. The discharge path of the water treatment process from the upper reservoir is not instrumented in this version, so the reservoir mass balance is only partially observable.
17. P4_HT_LD (hydro machine load demand) exists in HAI 20.07 and 21.03 but was removed from 22.04 and 23.05. The grid balance P4_LD against the sum of machine allocations therefore cannot be closed.
18. Unit inconsistency in the frequency deviation tags: P4_HT_FD is given in mHz and P4_ST_FD in Hz, yet both share a range of +/-0.02. A common unit must be established before a shared frequency invariant is defined.
19. The scaling and transport delay between P1_PIT01 / P1_TIT01 and their digitised counterparts P4_ST_PT01 / P4_ST_TT01 are not documented; they must be identified from normal data.
20. Per-tag acquisition behaviour on the OPC gateway (update rate, deadband, hold-last-value on communication loss) is not documented. This directly affects frozen-signal statistics and residual delay estimates.
21. No operating-mode labels are provided. Mode segmentation for the D2, D3 and D4 detectors must be derived from P1_STSP, P2_OnOff and P2_MASW, or supplied by an ICS engineer.
22. The four normal-operation files may not represent a single homogeneous configuration. Regime homogeneity must be checked before pooling them for calibration.
